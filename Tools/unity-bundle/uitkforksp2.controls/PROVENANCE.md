# Vendored subset of `uitkforksp2.controls` (build input for `build-ui-bundle.sh`)

**Status for this project (FlightPlan -> Redux 0.2.8.5).** This directory was inherited verbatim
from the K2-D2 v1.2 toolchain (`mods/K2D2Redux-v1.2/Tools/unity-bundle/uitkforksp2.controls/`),
which is where the pack was first vendored and measured. `Tools/build-ui-bundle.sh` still
hard-requires it (`[ -f "$PKG_SUBSET/Assets/Theme/KerbalUI.uss" ] || fail ...`), so it stays.

Whether FlightPlan's own UI actually needs it is a **P5 question**, not a P1 one and not yet
answered: the legacy UI's only use of a package control is
`UitkForKsp2.Controls.Dropdown` at `FP_UI.uxml:23,62`, and both sites are on the port's REVERSE
list (replaced by the native `UnityEngine.UIElements.DropdownField`). If P5 confirms the rebuilt
`FP_UI.uxml`/`FlightPlanTheme.uss` reference no `UitkForKsp2.Controls.*` element and no
`KerbalUI.uss`, the pack becomes dead weight — but the *script's* requirement must be relaxed
deliberately at that point, not by deleting this directory.

Everything below is the pack's provenance as measured for the K2-D2 port, and is retained
because it is the reason these exact bytes (and their `.meta` GUIDs) are here.

Why this directory exists
-------------------------

The K2-D2 v1.2 UXML roots on

    <UitkForKsp2.Controls.AppShell name="MainFrame" title="K2-D2"
        close-button-name="close-button" icon-texture="...">

and adds a package style reference to
`Packages/uitkforksp2.controls/Assets/Theme/KerbalUI.uss`. The package is declared in that
project's `Packages/manifest.json` as a GitHub dependency but is **not present on disk** anywhere
(not in the repo, not in the SDK, not in the game install), so the minimal bundle-build
project generated by `Tools/build-ui-bundle.sh` cannot resolve either the custom control
type or the stylesheet. This directory supplies the package assets.

Source
------

    git clone --depth 1 --branch 26w35a https://github.com/UitkForKsp2/UitkForKsp2.Unity.git
    # tag 26w35a -> commit 113ca2964bf10a7735662c80c59cdcd202e906b7
    # (the ref declared by K2D2Redux-v1.2/Packages/manifest.json)

`AppShell.cs` is byte-identical between tag `26w33a` (declared by v1.1) and `26w35a`; only
`Runtime/Tooltip.cs` differs between the two tags. The shipped 0.2.8.5 assembly
`$KSP2/KSP2_x64_Data/Managed/uitkforksp2.controls.Runtime.dll` contains the same attribute
name strings the v1.2 UXML uses (`close-button-name`, `icon-texture`, `title-spacing`,
`uppercase-title`, `icon-address`, `show-close-button`), so this era of the source matches
the shipped runtime.

What is included (and what is not)
----------------------------------

Included, with original `.meta` files so the GUIDs the UXML/USS reference resolve:

* `package.json`, `LICENSE`
* `Assets/Theme/KerbalUI.uss` (guid `48c501354e05fdc41b817de07ca2a1b8`)
* `Assets/Theme/Sprites/**` (all 50 sprites, incl. `resize-handle.png`, `control-frame.png`)
* `Assets/Theme/Fonts/{JetBrainsMono,LEDCounter7,SFPixelate,RosesAreFF0000}/**` (the fonts
  `KerbalUI.uss` and the K2-D2 stylesheet reference; JetBrainsMono-Regular is guid
  `f5454c9c675002c44a5a7234bd40c390`)

Deliberately excluded:

* `Runtime/**` — the runtime assembly is provided by the **shipped** 0.2.8.5
  `uitkforksp2.controls.Runtime.dll` copied in as a managed plugin, so editor and game
  agree on the UXML attribute set exactly. The package's `.asmdef` also references two
  package GUIDs that the minimal project cannot resolve.
* `Assets/Theme/Fonts/{HarmonyOS_Sans_*,NotoSans,NotoSansMonoCJK}/**` (~130 MB of CJK/UI
  fonts). Only `NotoSansMonoCJKtc-Regular SDF.asset` (guid
  `7e59a668a0d7f70429ea9a2737af9ff9`) is referenced by the K2-D2 stylesheets; that
  reference was already dangling in the proven-working v1.1 bundle and is tolerated as a
  load-time warning only.
* `Assets/Templates/**`, `Assets/Theme/Icons/**`, `Samples~/**` — not referenced by the K2-D2 UI.

**Note for FlightPlan's own fonts.** FlightPlan's UI ships its own 11 TMP SDF font assets
(`LiberationSans-*`, `Orbitron-*`) in the mod's own asset tree — they are *not* part of this
pack, and the pack's JetBrains/LED/pixelate fonts are not FlightPlan's typefaces. See
`research/notes/phase-3-flightplan-ui.md` §5 for that font set and its material state.
